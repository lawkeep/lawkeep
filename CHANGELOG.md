# Changelog

All notable changes to lawkeep are documented in this file.

The format is based on [Keep a Changelog](https://keepachangelog.com/en/1.1.0/), and this project
adheres to [Semantic Versioning](https://semver.org/spec/v2.0.0.html) (written as PEP 440
versions). While lawkeep is 0.x, a minor version may change behaviour.

## [Unreleased]

### Added

- `CONTRIBUTING.md` with the project's naming conventions (branches, Conventional Commits, pull
  requests, versions, tags, releases, changelog), a pull request template, `SECURITY.md` and
  Dependabot updates for GitHub Actions and Python dependencies.
- Repository setup for contributors: issue forms (bug report, feature request), a Code of Conduct
  (Contributor Covenant 2.1), `CODEOWNERS`, `.editorconfig`, pre-commit hooks
  (`.pre-commit-config.yaml`, including lawkeep's own pre-commit check), README badges, and
  workflows for dependency review, Conventional Commit PR titles, OpenSSF Scorecard and the docs
  site on GitHub Pages (https://lawkeep.github.io/lawkeep/).
- LLM-friendly docs following the llms.txt convention, served at the docs site root:
  [`llms.txt`](https://lawkeep.github.io/lawkeep/llms.txt) (summary, key facts, result codes,
  rules for agents, links), [`llms-full.txt`](https://lawkeep.github.io/lawkeep/llms-full.txt)
  (the whole reference in one Markdown file: concepts, every command with its exact options,
  result codes, `--json` fields, file formats, the `@law` API, the agent rules, MCP tools, the
  GitHub Action, known limits), `index.md` (the onboarding guide as Markdown) and Markdown copies
  of the guides and docs. They are generated by `scripts/build_llms_docs.py` from the CLI parsers,
  `action.yml`, the agent instructions and the docs; CI fails when they are out of date. The
  onboarding page links to them in its `<head>`.
- A public documentation website at https://lawkeep.github.io/lawkeep/, built with Sphinx, the
  Furo theme and MyST Markdown from `docs/site/`: home, getting started, concepts (laws, drafts
  and approval, permissions by direction, law history and lock, the gate and result codes, law
  strength, protection report, waiting list and person present), guides (using lawkeep by talking
  to your agent, developer workflow, CI and the GitHub Action, long runs without a person,
  changing a law, unrecorded law changes), AI tools (Claude Code, Codex, Cursor, GitHub Copilot,
  MCP server, with what is verified and what is not), writing good laws (recipes, avoiding weak
  laws), reference, FAQ and known limits, contributing and this changelog. The command reference,
  the GitHub Action inputs and outputs, the Python API and the default `lawkeep.toml` are generated
  from the code by `scripts/build_llms_docs.py` and drift-checked in CI. Every page is also
  published as Markdown (`<page>.md`) for LLMs. CI builds the site on every pull request (job
  `docs site`, warnings are errors, plus a non-blocking link check).

### Changed

- `check --law` now suggests the closest law id when an id is mistyped.
- CI on pull requests runs only what the change touches: a first job (`changes`) lists the
  changed files; the tests (Python 3.10, 3.12, 3.13), both example projects through the gate and
  the action self-test run only when code changed, the `docs site` build only when the docs (or a
  file they are built from) changed, and `lint` (with the generated-docs drift check) when either
  did. `dependency review` runs only when a dependency manifest, `action.yml` or a workflow
  changed. Jobs are skipped with a job-level `if:`, so required checks report "Skipped" and never
  wait; pushes to `main` still run everything. See `CONTRIBUTING.md` → "What CI runs".
- The website's front page is now the user documentation. The internal onboarding guide for
  contributors moved to https://lawkeep.github.io/lawkeep/contributing/onboarding.html (the old
  `/onboarding.html` redirects there) and its Markdown version from `docs/index.md` to
  `docs/onboarding.md` (served at `/contributing/onboarding.md`). `llms.txt` now links to the
  Markdown copies of the new pages, with the onboarding guide under "Optional".
- `docs/guide/` (developer guide, non-technical guide, law recipes) was folded into the website and
  removed; its Markdown copies under `/guide/` are no longer published.
- README: the status now says lawkeep 0.1.0 is released on PyPI (Alpha) and links to the docs
  website.
- GitHub Action versions: `lawkeep/lawkeep@v0` is now a moving tag on the newest final 0.x release
  (it gets fixes); pin `@v0.1.0` or a commit SHA for an exact version. The release workflow moves
  `v0` after each final release (never to a, b or rc pre-releases, never backwards) and starts
  only for full version tags (such as `v0.2.0`), so the `v0` tag never starts a release. The docs, the
  templates and the workflow `lawkeep init --ci` writes all use `@v0`; the "pin a release tag" TODO
  in that workflow is gone.

### Fixed

- Guard: the "confirm `lawkeep approve`" question now appears only when a command actually runs
  `lawkeep approve` (also through `uv run`, `python -m lawkeep`, `bash -c`, `xargs` or Python's
  `subprocess`), not when the words only appear in text such as a here-document, a commit
  message, `echo`, or a string in Python code. `lawkeep approve --help` is no longer asked about.
- Guard: the question is written for the person and says what would be decided, one line per
  item (for example "Loosen “…” → “…” (looser: protects less)", "Add new law “…”", "REJECT: …"),
  or says plainly when lawkeep cannot tell. Codex's rules-file prompt uses the same plain words.
- CI: the planted-bug step now captures the gate's expected exit code under `bash -e`.

## [0.1.0] - 2026-11-23

First real release (0.0.1 was a name placeholder). Status: **alpha**, see README → "Known limits".

### Added

- **Laws:** `@law("plain-English sentence", inputs={...})` on pytest + Hypothesis tests.
- **Commands:** `init`, `draft` (a separate session of your own coding agent writes laws),
  `approve` (one waiting list: drafts, proposals, drafting-agent edits, unrecorded edits,
  unconfirmed approvals), `check` (the gate: `ALL LAWS HOLD` / `SOME LAWS FAIL`), `strength`
  (planted bugs, one-sided and vacuous laws), `propose` (stricter changes apply automatically,
  weakening waits for a person), `report` (law changes and "only review what your laws don't
  protect"), `hook`, `mcp`.
- **Law history:** `laws.lock` fingerprints and the append-only `laws/history.jsonl`; laws changed
  outside lawkeep are flagged.
- **Safety:** isolated law runs (`python -I -S -B`, one-way results pipe), side-door checks,
  deterministic verdicts, a cheating test suite.
- **Agents:** adapters for Claude Code, Codex, Cursor and GitHub Copilot on a shared base (CLI,
  MCP server, `AGENTS.md` instructions, git pre-commit hook); rules for long runs without a
  person.
- **CI:** a GitHub Action that runs the gate and posts one report comment (never blocks merges by
  itself); a tag-triggered release workflow with PyPI trusted publishing.
- **Output:** plain-English terminal screens (Rich); `--json` for agents everywhere.
- **Typed:** strict pyright; ships `py.typed`.

Not yet verified: real runs of the Codex, Cursor and Copilot adapters; Windows; the private pilot,
non-technical tester and 30-task evaluation (see `docs/PLAN.md`).
